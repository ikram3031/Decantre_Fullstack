# [AB-44] Add Strict imageUrl Validation in createProduct and updateProduct

## Change Summary

- **Module**: Backend (`src/core/controllers/ProductsController.js`)
- **Impact**: Product Create API (`POST /api/v1/products`), Product Update API (`PUT /api/v1/products/:id`)
- **Description**: Removed silent fallback to `PLACEHOLDER_IMAGE_URL` when `imageUrl` is missing, empty, null, or undefined. Both `createProduct` and `updateProduct` now return a `400 Bad Request` with a clear human-readable error message: `"Product image is required. Please upload an image before saving."` This prevents placeholder images from appearing on the live website for products that should have real images.

## Affected Files

- `backend/src/core/controllers/ProductsController.js`
- `backend/docs/AB/AB44.md`

## Business Impact

Eliminates placeholder product images on the live site. Ensures every product in the database has a valid uploaded image URL before being created or updated via the dashboard.

# [AB-43] Implement Natural Numeric Sorting for Attribute Values in Dashboard Controller

## Change Summary

- **Module**: Backend (`src/dashboard/controllers/attribute.controller.js`)
- **Impact**: Dashboard Attributes API (`GET /api/v1/dashboard/attributes`, `POST`, `PUT`)
- **Description**: Added natural numeric sorting (`Intl.Collator` with `{ numeric: true }`) for attribute values (e.g. "2 ml", "3 ml", "5 ml", "10 ml", "50 ml", "100 ml") in `getAttributes`, `createAttribute`, and `updateAttribute` handlers. This ensures attribute values are always returned and stored in correct ascending numeric order.

## Affected Files

- `backend/src/dashboard/controllers/attribute.controller.js`
- `backend/docs/AB/AB43.md`

## Business Impact

Eliminated out-of-order attribute value display in dashboard product variant presets and attribute management UI.

# AB41: Fix Image Upload 500 Error Handling & Server Diagnostic Logging

- **Date**: 2026-08-08
- **Impact**: Backend (`errorHandler.js`, `ImagesController.js`)
- **Description**: Fixed an issue where Multer validation and upload limit errors (such as field name mismatches or oversized files) triggered HTTP 500 Internal Server Errors due to missing status properties on `MulterError`. Enhanced Express global error handling to map `MulterError` to HTTP 400 Bad Request, increased upload size limit to 10MB, added error diagnostic logging via `logger.error`, and converted `errorHandler` to standard arrow function syntax.

## Changes Made

1. **[`errorHandler.js`](file:///c:/Users/mdikr/Documents/CODE/Decantre_Fullstack/backend/src/core/middlewares/errorHandler.js)**:
   - Converted function declaration to standard ES6 arrow function.
   - Added `MulterError` detection with friendly Bad Request (400) messaging for `LIMIT_FILE_SIZE` and `LIMIT_UNEXPECTED_FILE`.
   - Added `logger.error` call to capture error stack traces on production server logs.
   - Added fallback for `err.statusCode`.

2. **[`ImagesController.js`](file:///c:/Users/mdikr/Documents/CODE/Decantre_Fullstack/backend/src/core/controllers/ImagesController.js)**:
   - Updated Multer `fileSize` limit from 1MB (`1 * 1024 * 1024`) to 10MB (`10 * 1024 * 1024`) to support high-resolution product photos.
   - Updated file storage destination path and public URL generation to use `src/uploads` (`path.join(process.cwd(), "src", "uploads", dateFolder)`), matching backend project structure and static route mapping.

3. **Docker Compose Configuration**:
   - Added `/var/www/uploads:/app/src/uploads` volume mount to `docker-compose.prod.yml` and `docker-compose.yml` so uploaded files inside `src/uploads` persist directly to `/var/www/uploads` on the host machine.

## Verification

- Verified syntax with `node --check`.
