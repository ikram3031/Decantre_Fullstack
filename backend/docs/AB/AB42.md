# AB42: Refactor Order Update Logic, Query Resolution & Payment Auto-Sync

- **Date**: 2026-08-08
- **Impact**: Backend (`OrdersController.js`, `orderControllerHelper.js`)
- **Description**: Enhanced order update and payment sync handlers to support flexible order querying by MongoDB `_id`, `did`, or `orderNumber`, preserved product `productDid` and `concentration` schema fields, added dynamic `updatedBy` user fallback from authenticated JWT user tokens, and implemented dynamic payment status calculation (`paid`, `partial`, `pending`) supporting advance and partial payments across Cash, COD, bKash, Nagad, and Bank payment methods.

## Changes Made
1. **[`OrdersController.js`](file:///c:/Users/mdikr/Documents/CODE/Decantre_Fullstack/backend/src/core/controllers/OrdersController.js)**:
   - Updated `updateOrder` controller to query orders by `_id`, `did`, or `orderNumber`.
   - Added fallback for `updatedBy` to use `req.user.userId` when not explicitly resolved from request input.

2. **[`orderControllerHelper.js`](file:///c:/Users/mdikr/Documents/CODE/Decantre_Fullstack/backend/src/core/helper/orderControllerHelper.js)**:
   - Preserved `productDid` and `concentration` in `normalizeOrderItems`.
   - Updated `syncPaymentDocument` to calculate `paidAmount`, `pendingAmount`, `status`, `paymentPhone`, and `paymentMethod` dynamically for COD, Cash, bKash, Nagad, and Bank payments.
   - Updated `buildAllowedOrderUpdates` to sanitize order `status` to valid schema enums (`processing`, `shipped`, `completed`, `cancelled`) and accept `paidAmount` and `paymentPhone`.
