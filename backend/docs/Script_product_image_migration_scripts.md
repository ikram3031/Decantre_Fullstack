# Product Image Migration & Processing Scripts Documentation

এই ডকুমেন্টেশনে প্রোডাক্টের ইমেজ প্রসেসিং, WebP কনভার্সন এবং ডাটাবেস পা মেলানো (Path Matching) সংক্রান্ত ৩টি নোড ডট জেএস (`Node.js`) স্ক্রিপ্টের বিস্তারিত বিবরণ ও ব্যবহারবিধি দেওয়া হলো।

---

## 🛠️ সিস্টেমের ওভারভিউ (Overview)

ওয়েবসাইট ও API-এর পারফরম্যান্স বৃদ্ধির লক্ষ্যে প্রোডাক্টের পুরাতন এবং অসঙ্গতিপূর্ণ ছবিগুলোকে আধুনিক **WebP** ফরম্যাটে রূপান্তর, রেজোলিউশন অপটিমাইজেশন এবং MongoDB ডাটাবেসে সঠিক URL পাথ সংরক্ষণের জন্য এই ৩টি স্ক্রিপ্ট ধাপে ধাপে কাজ করে।

---

## 📄 স্ক্রিপ্ট ১: `scripts/update-product-image-paths.js`

### 📌 উদ্দেশ্য:
ডাটাবেসের মূল প্রোডাক্টগুলোর `imageUrl` এবং `thumbnailUrl` প্রসেস করা, লোকাল `uploads/` ফোল্ডার থেকে ফাইল খুঁজে বের করা, WebP তে কনভার্ট করা এবং ব্যাচ ফোল্ডারে সেভ করা।

### ⚙️ কাজের লজিক & ফিচার:
1. **লোকাল সার্চ লজিক (`findLocalSourceFile`):**
   - প্রোডাক্টের নাম থেকে বিভিন্ন কীওয়ার্ড (Keyword variants) জেনারেট করে লোকাল `uploads/` ফোল্ডারে থাকা ফাইলের সাথে ম্যাচ করানো হয়।
   - একই প্রোডাক্টের একাধিক ফাইল পাওয়া গেলে **সর্বোচ্চ ফাইল সাইজের (High Quality Original)** ছবিটি বাছাই করা হয়।
2. **WebP কম্প্রেশন & রিসাইজ:**
   - **`thumbnailUrl`:** ডাইমেনশন **`600x600px`** (Aspect ratio বজায় রেখে)।
   - **`imageUrl`:** ডাইমেনশন **`1200x1200px`** (Aspect ratio বজায় রেখে)।
   - **ডাইনামিক কোয়ালিটি (Dynamic Quality):**
     - সোর্স ইমেজের আকার `> 100 KB` হলে: Quality **`90%`**
     - সোর্স ইমেজের আকার `<= 100 KB` হলে: Quality **`100%`** (Uncompressed Quality)
3. **ফোল্ডার ব্যাচিং (Batching):**
   - ফাইলগুলো তারিখ এবং ব্যাচ অনুসারে ডিরেক্টরিতে সেভ হয় (যেমন: `src/uploads/YYMMDD01/`, প্রতি ৫০টি প্রোডাক্ট পর ব্যাচ বৃদ্ধি পায়)।
4. **ডাটাবেস আপডেট:**
   - রূপান্তর সফল হলে MongoDB-তে প্রোডাক্ট ডকুমেন্টের `imageUrl` এবং `thumbnailUrl` ফিল্ডে নতুন লিঙ্ক সেভ হয়।

### 🚀 ব্যবহারের কমান্ড:
```bash
node scripts/update-product-image-paths.js
```

## 📄 স্ক্রিপ্ট ২: `scripts/update-unmatched-product-images.js`

### 📌 উদ্দেশ্য:
প্রথম স্ক্রিপ্ট চালানোর পর যেসব প্রোডাক্টের সোর্স ফাইল প্রোডাক্টের সরাসরি নামের সাথে মেলেনি বা প্লেসহোল্ডারে রয়ে গেছে, সেগুলোকে ডাইরেক্ট DB-Path বা ফাইলনেম বা কীওয়ার্ডের সাহায্যে উদ্ধার করে নির্দিষ্ট `/src/uploads/26072600/` ফোল্ডারে সেভ করা।

### ⚙️ কাজের লজিক & ফিচার:
1. **পুনরায় ফাইল খোঁজা (`findSourceByDbPathOrName`):**
   - ডাটাবেসে পূর্বের যেকোনো ফিল্ড পাথ থেকে ক্লিন ফাইলনেম বের করে `uploads/` ফোল্ডারে সার্চ করা হয়।
   - এতেও না পাওয়া গেলে প্রোডাক্টের নাম দিয়ে পুনরায় কীওয়ার্ড সার্চ চালিয়ে সবচেয়ে বড় ফাইল সাইজের সোর্স ফাইলটি উদ্ধার করা হয়।
2. **কাস্টম ফাইল ফরম্যাটিং (Naming Standard):**
   - **`thumbnailUrl`:** `thumb_<product-slug>_<did>.webp`
   - **`imageUrl`:** `product_<product-slug>_<did>.webp`
3. **নির্দিষ্ট ফোল্ডারে সেভ:**
   - কনভার্ট করা সব WebP ইমেজ সরাসরি `src/uploads/26072600/` ফোল্ডারে সংরক্ষিত হয়।
4. **ব্যর্থ প্রোডাক্ট রিপোর্ট (`failed-product-images.json`):**
   - যেসব প্রোডাক্টের সোর্স ফাইল লোকাল ডিরেক্টরিতে একেবারেই খুঁজে পাওয়া যায়নি, সেগুলোর `did`, `name`, `_id`, `imageUrl` এবং `thumbnailUrl` বের করে **`failed-product-images.json`** ফাইলে লগ হিসেবে জমা রাখা হয়।

### 🚀 ব্যবহারের কমান্ড:
```bash
node scripts/update-unmatched-product-images.js
```

## 📄 স্ক্রিপ্ট ৩: `scripts/update-failed-placeholders.js`

### 📌 উদ্দেশ্য:
যেসব প্রোডাক্টের কোনো ছবি লোকাল ফোল্ডারে খুঁজে পাওয়া সম্ভব হয়নি (`failed-product-images.json` ফাইলে নথিভুক্ত প্রোডাক্টগুলো), সেগুলোর ডাটাবেস পাথে মানসম্মত গ্লোবাল প্লেসহোল্ডার URL বসিয়ে দেওয়া।

### ⚙️ কাজের লজিক & ফিচার:
1. **JSON লগ রিড করা:**
   - `failed-product-images.json` ফাইল থেকে সকল অনুদ্ধারকৃত প্রোডাক্টের তালিকা পড়ে নেয়।
2. **ডাটাবেস বাল্ক আপডেট:**
   - প্রতিটি প্রোডাক্টের `did` (বা `_id`) ফিল্ড ধরে MongoDB-তে `imageUrl` এবং `thumbnailUrl` পরিবর্তন করে **`"/uploads/product_placeholder.webp"`** সেভ করে।

### 🚀 ব্যবহারের কমান্ড:
```bash
node scripts/update-failed-placeholders.js
```

## 📊 এক্সিকিউশন অর্ডার (Recommended Workflow)

```bash
# ১. প্রথম ধাপে প্রাথমিক ইমেজ অপটিমাইজেশন ও ম্যাচিং
node scripts/update-product-image-paths.js

node scripts/update-failed-placeholders.js
```
