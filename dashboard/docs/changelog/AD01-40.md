### AD05: Product API Empty Response Fix — Skip/Limit Standardization
* **Date**: 2026-08-06
* **Impact**: Dashboard (Products table, pagination, search, filters) and Backend (productUtils.js)
* **Root Cause**: `buildProductFilter()` in `productUtils.js` had a skip list that excluded known query params (like `limit`, `skip`, `sort`) from being injected into the MongoDB filter. However, `"page"` was missing from this skip list. When the dashboard sent `GET /api/v1/products?limit=15&page=1`, the `page` param leaked into the MongoDB query as `{ page: "1" }`. Since no product document has a `page` field, every query returned zero results. The customer-facing frontend was unaffected because it uses `skip` (which was in the skip list).
* **Changes**:
  - Refactored [`use-products.ts`](file:///c:/Users/mdikr/Documents/CODE/Decantre_Fullstack/dashboard/hooks/core/use-products.ts) to use `skip` + `limit` query params instead of `page`, matching the frontend's standard approach.
  - Removed the POST `/api/v1/products/search` branch — all product listing now uses a single `GET /api/v1/products` call with query params (`skip`, `limit`, `q`, `category`, `brand`).
  - Added `"page"` and `"offset"` to the skip list in [`productUtils.js`](file:///c:/Users/mdikr/Documents/CODE/Decantre_Fullstack/backend/src/core/utils/productUtils.js) as a backend safety net.
